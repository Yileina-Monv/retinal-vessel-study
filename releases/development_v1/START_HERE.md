# 跨电脑开发与训练：冻结开发版本 v1

本版本冻结 470 张训练图、118 张开发验证图、12 张边界案例、FIVES 专用 FOV、训练集归一化统计、实际裁块/增强校验样例、初始化和依赖版本。正式训练步数与骨架损失边界规则尚未冻结。GPU 浮点轨迹不承诺跨型号逐位相同。

## 传输约定

暂按手动传输校验包执行，不依赖网盘。压缩包只复制已经封存的相对路径文件；`.venv`、运行中的检查点、旧训练结果和唯一结果登记处不随包复制。旧 4070 batch 对照包只适用于旧试验，不能替代本版本。

1. 将完整 release 包解压到新目录，不覆盖另一台电脑的现有项目。先比对包的 SHA-256，再进入目录。
2. 使用 Python **3.13.11**，运行 `environment/setup.ps1` 安装锁定依赖；该安装脚本只初检 3.13，下一步会进一步检查完整版本。保留现有代理规则。
3. 执行 `.\.venv\Scripts\python.exe -m retinal_release.verify`。逐文件校验数据、FOV、统计、代码、依赖，并重做实际裁块与初始化摘要。失败即停止，不能选择“忽略差异”。输出是该机器的实际验收，不能从另一台复制验证报告。
4. 把验证输出中的机器编号和 GPU UUID 返回唯一调度电脑。GPU UUID 可以通过 `nvidia-smi --query-gpu=uuid --format=csv,noheader` 查询。

## 唯一任务登记处

首次发放任务的电脑是唯一调度电脑，默认当前 5080。登记处位于 `.runtime/coordination/`，不放入双向同步、不复制、不在另一台重建同一研究的登记处。即使误复制，程序也会检查机器身份和登记处路径，拒绝操作。

当前支持的是 **M0 开发任务**。调度电脑发放一个唯一编号，固定数据版本、目标机器、GPU、种子、更新预算和微批量。举例（所有尖括号均须替换，不是可直接执行的任务）：

```powershell
.\.venv\Scripts\python.exe -m retinal_release.exchange issue --run-id <唯一编号> --target-machine <验证输出的机器编号> --gpu-uuid <GPU_UUID> --seed 2026 --steps <开发步数>
```

将 `.runtime/coordination/tickets/<唯一编号>.json` 交给目标电脑。目标电脑执行：

```powershell
.\.venv\Scripts\python.exe -m retinal_release.run <任务单路径> --max-seconds 3000
```

同一任务始终在原电脑、原 GPU 上续训；不同电脑领取不同任务编号。运行窗口改变不改变总预算。同一目录的并发训练与导出互斥。最多每 64 次更新保存一次完整状态，正常窗口结束会额外保存。若断电导致锁文件残留，必须先核实原进程已终止再人工恢复；程序不自动抢锁。

## 结果交接及防止旧结果覆盖

目标电脑先让训练正常暂停或完成，随后导出：

```powershell
.\.venv\Scripts\python.exe -m retinal_release.exchange pack runs/development_v1/<唯一编号> <新结果包路径.zip>
```

包包含完整模型、优化器、AMP scaler、随机状态、已消费样本、学习率历史及进度。任务完成只代表该开发训练预算完成，不代表正式实验和最终评价完成。

调度电脑接收后执行：

```powershell
.\.venv\Scripts\python.exe -m retinal_release.exchange ingest <结果包路径.zip>
.\.venv\Scripts\python.exe -m retinal_release.exchange status
```

仅登记通过校验的结果。进度只前进；旧进度被拒绝，相同步数的不同结果被拒绝，同一个包重复提交幂等处理。失败内容留在隔离目录，不能覆盖已接受结果。每个已接受版本保留独立目录。

**离线时无法知道另一台电脑的实时最新进度。** 状态显示的是“最后收到的进度”，未收到新结果时明确显示未知；没有自动实时同步或跨电脑全局锁的承诺。各窗口结束必须交回一次结果包，调度端验收后再据此更新项目结论。若以后改用实时共享服务，应另行验证，不能把网盘复制当成全局事务锁。

## 开发规则

- 可以在工作副本改代码；冻结运行目录中的文件一旦改变，验证会拒绝训练。新的代码/数据版本必须生成新的 release，不能改旧版本再沿用旧结果。
- 每个方法及种子的比较必须引用 release ID、任务编号、实际设备和被接受的检查点摘要。旧 M0 无 FOV 结果只作历史工程证据。
- 本版本 FOV 采用方形眼底图中心和输入图像估计半径的圆形视野，保留暗区，不是可见度掩膜；不能直接用于 HRF/CHASE 等外部图像。边界之外的原标签像素保留原文件并在 QA 中报告。
- 病例/左右眼标识仍未知；当前只能保证相同图像组不跨训练/验证，不能声称患者独立。
- 4070 尚未实测；跨 GPU 的数值比较和跨 GPU 接续训练仍未验收。当前禁止同一训练任务中途换 GPU。
