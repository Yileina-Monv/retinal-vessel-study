# M0/M1 开发试跑机时估算（RTX 5080）

2026-09-05。仅做计时与排期分析，没有新训练更新。原冻结代码与配置未修改。

## 估算前提

建议开发比较为同一个种子的 3 个配置：M0，M1 系数 0.1，M1 系数 1.0；每组 microbatch 4、accumulation 1、512×512。总步数尚未正式决定；本表中的 10,000 是排期方案，不是冻结值。各组采用一致计划总步数和学习率轨迹。

## 当前实测与推算

- 原 batch 研究在小规模缓存数据上测得训练循环 0.0884751 秒/更新，不能直接代表当前扩大数据流程。
- 本轮对当前 SkeletonDataset 取同种子打乱后的前 64 个裁块，组成 16 个 batch；cache_size=8，包含图像/目标图读取解压、张量堆叠、实际输入及五份辅助图指纹。CPU 串行开销均值 0.6862968375 秒/batch，P50 0.6864447、P90 0.70220165 秒。未调用模型、未更新权重。
- 上轮 M1 batch 4 零更新前向/反向检查暖态约 0.091–0.093 秒。它不含实际优化器更新，且样本量很小，只能作计算部分量级参考。
- 当前训练入口同步取数，不能把 CPU 与 GPU 时间按完全重叠计算。按约 0.78–0.85 秒/成功更新排期，再留存盘、初始化和波动余量。此为合成估算，尚非完整训练吞吐实测。
- 新指标在一张真实训练图尺寸、随机概率图上 CPU 耗时 0.989 秒，整图加载约 0.201 秒；没有验证集成绩或阈值选择。结合旧整图推理量级，118 张验证一次先预留 3–5 分钟。随机概率图的骨架密度与训练后预测不同，此估算需在试跑后校正。

## 场景

| 配置数与每组成功更新 | 全部训练循环量级 | 含验证、起始恢复联调、存盘和余量的占机时间 |
|---|---:|---:|
| 3 组 × 5,000 步 | 约 3.25–3.54 小时 | 约 4–5 小时 |
| 3 组 × 10,000 步 | 约 6.50–7.08 小时 | 约 8–10 小时 |
| 3 组 × 20,000 步 | 约 13.00–14.17 小时 | 约 16–19 小时 |

以 10,000 步方案为例，可在每组第 2,500/5,000/10,000 步各验证一次，总计 9 次，约 27–45 分钟。验证频率和比较总步数需要在实际签发任务前记入试跑方案；当前训练入口需暂停并另行评价，不会自动保存这些额外检查点。

建议预留 8–10 个 5080 GPU 小时，即约 3 个 3–4 小时窗口；实际窗口组合及收尾余量可能需要第 4 个窗口。这里的 GPU 小时是单卡任务占用时长，包括等待 CPU 取数期间，不是满负载 GPU 运算时间。

若先看半程结果，应先声明完整 10,000 步预算，在 5,000 步暂停，保持同一学习率轨迹；不能先以 5,000 步走完整个衰减，再临时改票据续成 10,000 步。三组都完成半程约需 4–5 小时，完整结果仍为 8–10 小时，总时间不相加。

## 优先处理的瓶颈

当前约八成以上的串行批次耗时在取数、解压与指纹环节。预取、目标图读取方式及已冻结输入的审计方式是后续优化候选，未实现或测速前不给承诺性加速比。若修改加载代码，必须新版本封装并保持样本指纹一致，不能修改已冻结包。该瓶颈解决前，旧正式训练 17–20 小时的预算也需要重新估算。

本表只覆盖开发阶段单种子三配置，不包括正式多种子实验，也不保证 10,000 步足够收敛或证明统计显著性。
