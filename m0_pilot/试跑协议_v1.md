# M0 一次工程短跑：预先确定的配置

记录日期：2026-09-04。用户授权：推进一次 M0。目标：建立真实数据训练、日志、完整状态保存恢复和整图预测入口，检查可学习性与资源占用。

## 1. 范围

沿用数据准备 v1 的 32 张试训和 8 张开发验证图。它们全部来自 FIVES 原始 600 张训练分区。原始 200 张测试图和外部数据不参与本次运行。质量字段只用于既有样本覆盖，不进入损失权重。

这是一轮固定长度的工程试跑，不是正式基线：仍按当前数据规则使用全部裁块像素、不生成 FOV，不做通道均值方差标准化，仅除以 255。与 Pro 执行建议中的正式 FOV/标准化方案的差异在此明确保留，正式实验前另行确定。

## 2. 模型与优化

| 项目 | 本次值 |
| --- | --- |
| 模型 | 2D U-Net，32/64/128/256/512 通道，双卷积、GroupNorm(8)、ReLU、转置卷积上采样，无 Dropout |
| 数据 | 原尺度 512×512 裁块，沿用已核验的同步几何增强 |
| 初始化种子 | 2026；数据选择和裁块种子沿用 20260904 |
| 损失 | BCE + soft Dice，二者权重均为 1 |
| 优化器 | AdamW，初始学习率 0.001，weight decay 0.0001 |
| 更新预算 | 256 次成功的参数更新 |
| 批量 | 微批量 2，累积 2 次，有效批量 4，共 1,024 次主线裁块抽样 |
| 学习率 | 256 步 cosine，最低 0.00001 |
| 梯度裁剪 | 全局范数 1.0，记录裁剪前范数 |
| 精度 | FP16 autocast，损失归约 FP32，动态缩放初值 1024 |
| 确定性 | 启用确定性算子，禁用 cuDNN benchmark 和 TF32 |
| 加载 | 2 个 Windows spawn 工作进程，沿用每进程最多 2 对 uint8 缓存 |

Dice 按每张裁块分别归约后取批均值；BCE 对批内全部像素取均值，因此固定大小的两次微批量累积与有效批量的损失权重一致：

\[
\mathcal{L}=\operatorname{mean}_{n,i}\operatorname{BCE}(z_{ni},y_{ni})+
\operatorname{mean}_{n}\left[1-\frac{2\sum_i p_{ni}y_{ni}+\epsilon}{\sum_i p_{ni}+\sum_i y_{ni}+\epsilon}\right],
\quad p=\sigma(z),\ \epsilon=10^{-6}.
\]

全背景裁块保留，使用相同像素损失。出现非有限损失、梯度或 AMP 跳过参数更新时停止并记录，不把被跳过的更新计为成功步数。每段进程设置 1,800 秒运行上限；超时保留已有检查点，不自动延长。

## 3. 学习检查与评价

- 固定训练诊断：从已确定的 4 张拟合检查图中固定 `epoch=0`、索引 0/4/8/12 的 4 个裁块，不增强；在初始和每 32 步记录损失、Dice。它们属于训练图，结果只反映拟合情况。
- 8 张开发验证图仅在初始化和第 256 步评价；固定二值阈值 0.5，报告逐图与图像宏平均 Dice/Precision/Recall，不搜索阈值、不选择最佳检查点。
- 整图预测使用 512 窗口、256 步幅，Gaussian 加权融合；FIVES 每张图 49 个窗口。保存最终 float32 概率图和 0/255 二值图。
- 空真值且空预测的 Dice 记为缺失值，预测为空时 Precision 记为缺失，真值为空时 Recall 记为缺失；宏平均排除对应未定义值。本次 8 张验证图的原标注均非空。
- 不设置基于本次小样本得分的研究成功门槛，不据结果扩展到多种子实验。

## 4. 检查点与独立进程续训

每 64 步保存完整检查点，包括模型、AdamW、学习率调度器、AMP scaler、Python/NumPy/Torch CPU/CUDA 随机状态、成功步数、下一个数据索引，以及代码/配置/清单指纹。

1. 第一进程运行到第 128 步，保存检查点。
2. 在同一进程中额外执行第 129–132 步作为“不中断参考”，保存样本、损失和完整状态摘要，然后退出。这 4 次更新仅用于恢复检查，不写入主训练历史。
3. 第二进程读取第 128 步检查点，重新执行第 129–132 步，与不中断参考比较，再继续到第 256 步。

验收要求：样本及几何一致；模型、优化器、调度器、scaler、RNG 和数据索引的状态摘要相同；主日志仅有连续的 1–256 步。总执行量为主线 256 次更新加 4 次恢复参考更新。

## 5. 交付与计时

保存曲线、训练日志、两次整图验证记录、最终预测、完整检查点、恢复比较和资源摘要。设备分配显存与保留显存分别记录；进程树 RSS 为离散抽样值，含共享页的重复计数可能，不冒充系统物理内存峰值。

训练步耗时包含取数与计算，并另记取数等待和 GPU 区域计时。数据重建进程、整图评价和检查点写入的耗时另在进程总时间中体现。本次测量不能直接代替大规模训练收敛预算。
