## 已完成的入口核验

2026-09-05 已执行 `python -m unittest discover -s tests -p test_batch_study.py -v`，4 项通过：实际像素损失的累积梯度归约、FP64 加权归约恒等式、精确符号翻转/Holm 算法、样本预算和学习率边界。

新入口的同 GPU 恢复测试：seed 2026、m2_a2_e4 在第 256 个抽样（64 次更新）暂停，独立进程继续至 2,048 抽样（512 次更新）；另做一次不中断的参考。模型、优化器、scaler、随机状态、位置和样本签名完全相同，512 次损失最大差为 0。参考重跑不计入 8 个独立种子。

实际排程记录：seed 2026 的参考组为恢复测试先行运行，因此这一个运行没有遵循随机组顺序；其余组按已保存的预定顺序运行。这可能影响微小的耗时比较，不能忽略初始化、温度和审计开销。

FP32/AMP 数值探针采用真实网络、4 个实际训练裁块、微批量 1/2/4、相同有效 batch 4。数值产物保存在 `runs/batch_study_v1/rtx5080/numerical/`。微批量变化后的梯度/输出不要求逐位相同；最终精度差异由重复训练的预设终点评价。

## 本轮可以回答与不能回答的问题

能回答：在当前 M0、32/8 开发集和 2,048 抽样预算下，微批量布局变化或有效 batch 变化是否显示可检测的 Dice 差异，及其区间是否跨越预设 ±0.01 容差。

尚不能回答：最终 FOV 方案、M1 骨架损失、扩大开发集或收敛预算下是否同样成立；测试/外部/患者级效果；没有 4070 实际结果时的跨 GPU 差异。

有效 batch 变化组固定样本量，不固定更新次数；学习率不随 batch 自动缩放。其差异包括同等样本预算下优化器更新频率变化的后果，不能写成“batch 增大本身必然损害最终精度”。

“精度”本轮主口径为图像宏平均 Dice，另报 Precision/Recall；不使用可能被背景像素主导的像素 Accuracy 替代分割质量。
