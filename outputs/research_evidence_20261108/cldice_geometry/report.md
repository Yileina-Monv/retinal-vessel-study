# B1/B2 误报机制与 clDice：研究审查报告

## 先说结论

我们确实找回了一部分原来漏掉的细分支，但同时增加了更多 GT 阴性的预测像素。新增误报多数依附已有预测，不是少数图片的大块孤岛；也不能简单解释为“真实血管整体变粗”。新增诊断进一步发现：**GT 骨架覆盖增加，但预测骨架落在 GT 外的比例也增加，最终 clDice 同样下降。** 因此当前问题是召回与精确率的失衡，不是换一个结构指标就能宣称成功。

首选下一轮方向：**保留原 BCE+Dice，只增加一个小权重 soft-clDice 候选，不再叠加 B1/B2 的正样本骨架 BCE。** 理由不是论文级别，而是它提供当前辅助项缺少的“预测中心线是否落在 GT 内”的约束。这一机制与现有证据相符，但不能保证减少所有 FP，更不能保证 Dice 提升。先做工程检查，再决定是否批准一条固定预算探索。

原三种子 T0/TW 负面结论不变；B1/B2 是 seed=2026、反复使用的 Dev28 探索。新增 clDice 只是诊断，不能替换原冻结主指标或保护条件。原人工审核保持 0/26，专家状态 NOT_ASSESSED。本次没有 GPU、训练、模型推理或官方 Test。

### 3. 为什么 Recall 上升而 Dice 下降？

这是可由 TP/FP 账目解释的现象，不需要假定训练出错。新增预测像素中，只有约 38.01%/37.57% 属于 GT 阳性；消除 FP 的数量又不足以抵消新增 FP。21/28 图的 Dice 下降，两组所有图 Precision 下降、FP 增加。不能用合并像素 Dice 取代图像宏平均，但逐图恒等式均已核对。

固定 GT 阳性数量 N，Dice = 2TP/(N+TP+FP)。增加 TP 有收益，增加 FP 有成本；目前这种组合使宏平均 Dice 下降。**找回细分支是真的，受保护的整体分割成功尚未实现也是真的。**

### 4. 哪些原因已经证实，哪些没有？

已证实：上述集合数量、空间距离、依附关系、结构精确率下降，以及当前辅助项只有正样本方向。没有发现本次结果可归因于重复归一化或 λ 重复应用的新证据。

合理机制假设：正样本骨架项通过共享网络参数提高一类血管样响应，既恢复 GT 分支，也放大部分 GT 外响应；相同 λ 不代表 B1/B2 相同梯度剂量，完整路径中较容易点也可能稀释困难点的梯度。**这些是机制解释，不是由现有终点输出完成的因果证明。**

仍未知：每个 GT 外细长区域究竟是背景、真实血管漏标、边界争议还是错误连接。已有 Sol 图像查看仅覆盖 10 张诊断图、9 张 Dev，不等于医学审核。既有图册中的可能漏标、背景/斑块样和未知例均保留；不要求用户重新判断 26 张图，不虚构各医学类别百分比。

## 第二部分：clDice 论文真正做了什么？

### 1. 指标与公式

设预测为 P、GT 为 G，骨架为 S。论文 §2、式(1)(2)：

`Tprec = |S(P) ∩ G| / |S(P)|`

`Tsens = |S(G) ∩ P| / |S(G)|`

`clDice = 2 Tprec Tsens / (Tprec + Tsens)`

通俗地说：第一项问“预测画出的中心线，有多少在 GT 血管里”；第二项问“GT 血管中心线，有多少被预测覆盖”。普通 Dice 更重视面积，小支路丢失可能只少一点面积；骨架覆盖对这些支路更敏感。但 clDice 仍按骨架点计数，不是每条支路同等权重，也不是逐条连接的严格正确率。

**硬 clDice 是评价指标；soft-clDice 是用于训练的可微近似。** 论文 §4.1、算法1/2用 min/max pooling 反复腐蚀、开运算和 ReLU 提取软骨架。梯度经池化极值位置和比值传播，不是对硬二值化求导，也不保证每个像素都有稳定、均匀的梯度。

### 2. 论文怎样组合 Loss？

§4.2 式(3)：`L = (1−α)(1−softDice) + α(1−softclDice)`；考察 α=0.1–0.5。论文基线是 softDice，不是我们现有 BCE+Dice。将它用于本项目必须明确是适配：保留 A0 原系数，再加一个独立 η 项；不能照抄 α 就说和旧 λ 等效。

§3 的拓扑结论要求相应前景/背景骨架包含条件，不能把前景 soft-clDice 的近似高分解释成连接全部正确。§4.3 的实际实验采用前景项，是工程选择，而不是取消理论假设。

### 3. 实验是否保证 Dice、Precision、Recall 同时改善？

**不保证。** 主文 §5.3、表1 的 DRIVE FCN：Dice/clDice 从基线 78.23/78.02 到 α=0.2 的 78.75/80.22；但 α=0.4 为 78.00/80.43，α=0.5 为 77.76/80.95：结构分数增加，Dice 反而下降。DRIVE U-Net 从 74.25/75.71 到 α=0.5 的 75.21/76.86。效果依赖模型与权重，不能只引用有利行。

表1没有同时提供像素 Precision/Recall，不能据此宣称二者都提高。补充材料 §4 描述 DRIVE 的 30 图三折、10 图留出，并按验证 clDice 选模型；与本项目固定终点、重复 Dev 不同，不能照搬择优 Checkpoint。论文没有直接验证 MAPLES-DR 或我们的候选路径定义。

主文 §5.3 计算效率给出 RTX8000、batch4、1024² 下总步时 1.24→1.35 秒，约增加 9%；这是该配置实测，不是 A7 显存/耗时保证。软骨架复杂度随迭代 k 和面积增加，最大池化与比值项也需要实际梯度、AMP 和空目标测试。

### 4. 对四类错误的实际能力

|错误|可能约束|重要盲区|
|---|---|---|
|真血管附近预测变粗|原 BCE+Dice 仍约束面积|中心线仍在 GT 内时，clDice 可完全不罚；合成例已验证 clDice=1 而 Dice<0.8|
|背景假血管|预测骨架在 GT 外会降低 Tprec|短小散点、未改变骨架的边界扩张可能弱约束；GT 漏标也被罚|
|分支断裂、细支漏分|GT 骨架未覆盖会降低 Tsens|一个关键短断口占比小，分数仍可高；不等同图路径连通性|
|GT 可能漏标|无法自动辨认|会把真实但未标血管当错误；不能靠 Loss 解决标签真实性|

已固定仓库提交 `47d31a6cc4a8101b1ffe8052994821961e57af9f`，原文、补充材料和源码存于 `sources/`。

## 第三部分：它适不适合我们的项目？

### 1. 与现有方法的数学机制

|方法|增加的驱动力|FP 是否受辅助项直接约束|
|---|---|---|
|A0 BCE+Dice|原整体前景/背景分割|有，仍保留|
|B1/B2 正样本骨架 BCE|选中 GT 骨架处推高概率|辅助项没有负样本；并非整个模型无背景监督|
|ECCV2024 Skeleton Recall|GT 骨架/细带上的概率均值提升|主要是单向召回，不增加预测结构精确率项|
|soft-clDice|GT 骨架覆盖与预测骨架支持的调和约束|有结构层面约束，但不是所有像素 FP 的约束|

现有辅助 BCE 为每 crop `sum(S*softplus(−z))/max(sumS,1)` 后对固定 batch 平均，空 crop 贡献 0；实际科学系数为 0.03。对选中 logit，辅助梯度是 `λ*S*(p−1)/(B*N)`，背景为 0。较低置信正样本仍有较强推动。

Skeleton Recall 论文 §3.2、算法1在 CPU 生成 GT 骨架，可膨胀后与 GT 相乘，形成 GT 内细带；§4.4 将召回项加入普通分割 Loss。作者实现固定在提交 `c7bac3c72ca7bb4f3d891235f051f0c4d07d7229`。概率平均召回对 logit 的梯度含 `p(1−p)`，非常低概率处会衰减；它不是 BCE 的同义替换，也没有自动补上 FP 判别。DRIVE 表2的 Dice/clDice 有小幅变化，不能外推为本项目 FP 保护成功。

soft-clDice 恰好补上当前缺少的一侧，因而值得优先做**受控可证伪试验**。但我们的误报不是已证实全为假骨架；如果它主要惩罚了漏标血管，或仍只扩大预测半径，就可能再次 Dice 下降。梯度经过软骨架和分式，仍可能超过 A0 或方向冲突；不能靠系数小就豁免工程门槛。

### 2. 为什么现在不优先上 SkelCon 全套？

SkelCon 的原作者摘要及公开代码强调血管—背景特征判别；`proj/nets/sample.py` 涉及按 GT/置信度选择血管、背景/边缘样本，`siam.py` 涉及投影及特征学习。这提供背景判别的备选机制，但同时引入特征头、采样及额外训练选择，变量更多；GT 漏标时困难负样本还可能打压真实细血管。

本轮没有取得 SkelCon 完整出版正文，故**不声称已审阅其完整消融或复现其损失**；依据仅限出版社/作者摘要和固定提交 `0e617a7eca85eeda2d291f483014ddecdffc8a08` 的源码。当前已有更小变量的结构精确率假设可检验，不必直接搬整套网络。

## 第四部分：下一步只推荐一条路线

### 研究假设与候选

**候选 C：A0 原 BCE+Dice + η·soft-clDice；不含 B1/B2 辅助 BCE。** 假设：预测骨架精确率约束可在保留细分支召回收益的同时，减少 GT 外中心线和 FP 成本。若 TP/FP、Dice 未改善，该假设可被否决，不以 clDice 上升单独宣布成功。

建议工程候选 η=0.03，一次固定，不做 Dev 扫描；只是保守名义起点，不是由旧 λ 推导的等剂量。若真实梯度超门槛，应停并另行批准，不能自动调参。原 U-Net、M0、seed2026、样本/增强序列、batch、优化器、学习率、2000 成功更新全部保持；不从 B1/B2 终点续训。A0 可复用的前提是完整来源及配对一致性再次确认。

这是 C 对 A0 的单个新辅助项对照；与 B1/B2 比较时同时涉及监督范围与函数机制，不能宣称只隔离了“精确率这一项”的纯因果效应。既有 B1/B2 为固定参考，不重新挑终点。

### 先完成的工程定义，不是当前训练许可

1. 单前景概率、原 FOV；原 BCE/Dice 完全不变。软骨架处理 FOV 的裁切、边缘 padding、空目标和分母平滑须写清楚。建议逐 crop 计算、固定 batch 平均、平滑1；这是对作者跨 batch 聚合的显式适配。
2. 工程试算可用作者实际 k=10；**科学训练前必须依据 Train GT 的宽度/腐蚀覆盖检查冻结 k**，不看 Dev 选 k。过少会漏粗结构，过多增加成本。禁止复制作者被忽略的 iter_ 参数。
3. CPU 检查 λ0 精确退化、空 GT/FOV、孤立点、细/粗管、断裂、GT 内外假支和缩放变换。目标只由 Train GT 产生，不使用 Dev 错误位置制作训练标签。
4. 用户另行批准后，建议最多32次固定 GPU 诊断、零更新：8个原固定 Train 批次×FP32/AMP×零/非零系数。检查真实未缩放参数梯度、辅助/A0 L2 与 cosine、有限性、AMP及实际显存。沿用 ratio>2 暂停，负 cosine 记录并按冻结规则处理，不等同发散。
5. 再另行批准一个**新账本**的最多100次工程成功更新：同初始化连续50，与25+恢复25配对，核对模型/优化器/调度器/AMP/RNG/采样状态及逐步日志。失败/不明事件按批准账本规则保留并计费，不挪用或清零历史 G2 400 次预算。此处仅为待批建议，不能自动启动。

### 成本、收益与否决标准

## 技术附录：复算口径与证据入口

新指标固定原生2D Zhang骨架（skimage0.25.2），P=(prob≥0.5)∩FOV，G=GT∩FOV，包含原全图评价的 U 区；无d1容差、膨胀、连通修复或组件筛除。与作者评价同为硬骨架包含率，但增加FOV、明确空规则、固定图像宏平均。它不是原细路径 d1 指标的替代品。

空分母分项记NA；双方全空 clDice=1、仅一方空=0、非空而两项和0时=0。本次84组均非空，规则不改变实际结果。1000次图像bootstrap复用原结果相同索引。9组合成检查及输入前后SHA核对通过；断裂反例说明高 clDice 不等于严格连通，增粗反例说明高 clDice 不等于边界准确。
